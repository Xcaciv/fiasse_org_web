Secure is a state.
Securable is a property.

States expire — new CVEs, new techniques, new dependencies, zero commits required. Securability is the engineering property that lets software absorb tomorrow's threats at the speed of ordinary development. FIASSE is the framework for building it — for the engineers writing your code and the agents writing more of it.

One directive, four values

Resiliently add computing value.

That is software engineering's primary directive, and every word is load-bearing: value is why the business funds the work, add because delivery is continuous, resiliently because each change must leave the system able to withstand what follows it. The four values orient every FIASSE practice:

Securable AttributesoverSecurity Controls
ParticipationoverAssessment
Engineering First PrinciplesoverSecurity Jargon
Business ValueoverSecurity Activity

Both sides have worth. When choices must be made, FIASSE favors the left.

The model

SSEM: securability in ten attributes engineers already respect

A design language, not a control catalog. No exploit trivia, no hacker mindset required — the same vocabulary guides a merge review or an AI agent.

Maintainability

Elemental security
  • Analyzability — assess impact fast
  • Modifiability — change without fear
  • Testability — prove it still works
  • Observability — see state in outputs

Trustworthiness

Systemic security
  • Confidentiality — keep secrets secret
  • Accountability — every action traceable
  • Authenticity — verify identities

Reliability

Universal security
  • Availability — up when it matters
  • Integrity — accurate, intact
  • Resilience — recover and continue

Where's Authorization? Deliberately absent — authorization is a security feature you specify per context, not a property code simply has. SSEM supplies everything a sound authorization feature depends on. The full answer →

The mechanism · FIASSE §5.2

Guardrails, not gates.

Every merge produces a Securability Report. Nothing blocks by default. Gating is a policy decision the business owns — and the paper trail satisfies auditors as a by-product of ordinary work.

01
Securability Report
Automated signals + SSEM-vocabulary review, scoped to the changeset. Every merge, unconditionally.
02
Advisory Default
Visible consequences at the moment change is cheapest to discuss. A teaching instrument first.
03
Gating by Policy
Teams elevate chosen finding classes to blocking. Overrides exist — and record who accepted what, and why.
04
Audit Trail
Timestamped, attributable, reviewable. Maps to EU CRA and NIST SP 800-218 without a separate evidence hunt.
05
Posture over Pass Rates
A recurring override isn't a compliance failure — it's a signal pointing upstream to a requirements gap.
